## 2. How to work: Opus coordinates, Sonnet and Haiku do bounded tasks

The owner asked for the main session to run on Opus and farm out smaller tasks to cheaper models, and
wants to **evaluate** that. The rules that make it safe:

| Who | Does | How |
| --- | --- | --- |
| **Opus** (the main session) | design and decision records; security-sensitive code (identity, secrets, tokens, the proxy, cloud IAM); reviewing every sub-agent's diff; planting the faults (rule 15); deploying and every live check | the only agent that runs `make refresh`, the throwaway test stack, `docker`, commits |
| **Sonnet** sub-agent | implementation with a fixed design and named tests (a store and its tests, a Glass screen from a written layout, a CLI verb) | `isolation: "worktree"`; never touches the shared stack; hands back a diff that Opus reviews, re-runs and merges |
| **Haiku** sub-agent | read-only surveys, reference sweeps ("every mention of X"), licence and dependency checks, spec-consistency checks | read-only; changes nothing |

- **Rule 14 holds.** Only one agent at a time runs against the working tree's stack. A sub-agent that
  has handed back a report is confirmed stopped (`ListAgents`) before Opus touches the containers.
- **A sub-agent's prompt is self-contained.** Give it the spec sections, the files and the named tests
  from this note. A cheap model that has to rediscover the spec costs more than it saves.
- **Opus repeats every plant itself.** A sub-agent's "tests pass" is not evidence until Opus has shown
  each new test red (rule 15).
- **Evaluation.** The tasks marked **[trial]** below are run on the cheaper model on purpose. For each,
  record in the build plan: tokens (from the agent's usage line), whether its tests survived Opus's
  plants, how much Opus had to change, and whether it followed the spec's wording and British English.
  After three trials, decide the default.

## 4. Things a new session would otherwise trip over

- **`docker exec` needs `-i`** for a Python heredoc, or nothing runs and nothing is printed.
- **The analytics DuckDB is locked by the running Conduit.** Probe it from inside the API container,
  or stop the Conduit (seeds do).
- **Superset's guest-token path is proven live; its permission names are Superset's own.** Use
  `get_schema_perm` with the catalogue, never a hand-written name.
- **Never print a secret.** To check one, test a token grant and print only granted or refused.
- **The owner signs in.** Never type a password. Every `make refresh` signs the owner out, so batch
  deploys and say when one is needed.
