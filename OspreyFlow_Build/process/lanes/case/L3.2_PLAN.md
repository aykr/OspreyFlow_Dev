# Case lane · L3.2 · plan (8 November 2026)

Working from ADR-144 and its Amendment 1, ADR-143 decision 1 and Amendments 1–2, ADR-099 Amendments
13–15, ADR-146 decision 6 (*Open the evidence*), and spec 01/02/03/04 wherever they name a branch.
The reach today: 148 Core files and 80 Build test files name "branch" (some of them mean a pipeline
DAG's branch or a git branch, which stay).

## Parts, in order, each test first

- **A. Schemas, alone and first.** Add `CaseView`, `CaseViewCreate` and `CaseViewRead` (the latter
  counts `missing`, never names them) to `packages/schemas` and regenerate the types. This goes to
  the orchestrator as its own commit.
- **B. Views: store and routes.** `services/api/case_views.py`, in memory and on Postgres, and
  `/v1/investigations/{id}/views`: list, create, open (a live re-read), share, delete. Tests come
  first:
  - ADR-144's four tests;
  - an access test on each read path (rule 4);
  - an existence-leak test: a view a reader has partly lost access to shows only a count, red with
    stored items returned;
  - a private view refused to another member as 404, not 403;
  - delete never cascades.
- **C. A branch's unnamed writes (item 3), test first.** These are proposals, extractions and
  `ALERTED_ON` written in a branch the migration hasn't reached yet, touching a node in the
  original case's layer. Every request scoped to such a case is refused before anything is
  written. The test is red with the layer check removed, at the real accept and alert call sites.
- **D. `scripts/migrate_branches_to_views.py`, dry run first.** Each branch becomes one view of its
  original case, holding the branch's node set, layout, window and threshold. What only the branch
  held, and anything in a legacy branch's or pre-L3.1 jump case's own layer, moves into the
  original case's layer, tagged `from_branch`. The branch case is then removed (soft, so its audit
  stays linked from the view). A case it cannot place is reported, never guessed. Tests:
  - the dry run writes nothing (red with one write planted);
  - the real run leaves every seeded case with its views and no branch;
  - a re-run changes nothing.
- **E. No branches anywhere.**
  - Remove: the routes `…/branch` and `…/branch-by-filter`; `branch_*` in the working set;
    `event_scope`'s branch-family inheritance; `branch_window`; `branched_from` from the API;
    `datasets`' `case_layer_reads` and branch paths; `branchNodes.ts`; `branchByFilter.ts`.
  - Replace in the Glass: the Cases tree becomes a list of cases, each with its views (boards
    later, L3.3); the selection bar's *Branch* becomes *Save as a view*; the over-cap dialog's
    branch option becomes *Save as a view*; a *Views in this case* panel; the GOV.UK list and form.
  - Keyboard and harness: `keyboard/views.spec.ts` (save, share, delete, open; the selection bar's
    view action), with the registry ids as a diff. Axe in dark, light and GOV.UK.
  - A 404 test for `/v1/investigations/*/branch*`.
- **F. `tools/no_branches_check.py`.** It scans `apps/workspace/src` and `services/api`, allowing
  the pipeline DAG and git meanings by a named list. It is shown red first with one planted word
  (the real shape: an identifier in a `.tsx` file and a route string), with
  its own test file under the Build tests. The Makefile and `ci.yml` wiring goes to the
  orchestrator as a diff.
- **G. The words in `spec/00`–`09`,** leaving earlier ADRs as written.
- **H. Carry: axe `target-size`** on `case-screen-options-harness.html` variant c (dark and light).
  The harness's axe case is shown red first.
