## Order (each step red first, rule 15)

### 0. `packages/schemas`, alone and first (ordering 2)
- `TargetModel`:
  - dataset_id, version, state `draft | live | previous`, packs (pinned versions), extensions (each with `retired_at`), and list refs.
- `ReferenceList`:
  - dataset_id, key column, version, `kind` (`screening` as ADR-140 A9 decision 3 names it, which replaces the plan's "screening flag"), and its schedule. It absorbs `ListSchedule`.
- `DatasetKind` gains `drawn`.
- `HomeCase` (dataset_id, investigation_id), or a `home_of` field on the investigation. One per dataset per deployment (question 4, below).
- `MakeLiveInput`:
  - owners: people, and later teams; the maker proposed first.
  - Refusals, in words: none given, a service account, and an owner kind the System setting forbids.
- The Admin › System setting *Dataset owners may be*: `people_and_teams | people_only | teams_only`.
- The `edit_target_model` right (ADR-126 A2 names it; it isn't in `schemas/rights.py`), its row in the role table, and its route check.
- Generated TypeScript regenerated (`schemas-check`).

### 1. The target model's store and routes (spec 01, spec 03)
- A new store module for target models in the Conduit (`target_models`, to be made), Postgres and in memory:
  - exactly one live model and at most one draft per dataset, enforced in the store (a partial unique index);
  - a second draft is refused in words;
  - revert makes version N+2 and never rewrites N.
- Routes under `/v1/datasets/{dataset_id}/model`: open draft, save draft, discard draft, impact, make live, and revert as a new draft. Behind the dataset's gate (ADR-140 A4) and `edit_target_model`, each with an access test (rule 4).
- Extensions are retired, never deleted. POLE core types cannot be removed or renamed.
- **The impact view:** pipelines that write a changed or retired type, reusing `pack_versions_for`'s flagging.
- **Make live:**
  - pauses those pipelines' schedules, with the reason;
  - a deployed pipeline pins the live version it was deployed against, and a Test run may name the draft version;
  - editing never changes what a running pipeline reads.
- Tests come from phase 5 item 1, each red: the second draft; editing versus a running pipeline; flagging exactly the right pipelines; revert's N+2.

### 2. The pipeline's domain-model node removed (phase 5 item 2)
- A v1 recipe reads its model from the dataset. The recipe migration is a dry run first.
- This is Lane 1's file set (`ingest/recipes`, the pipeline editor). It is built only as agreed, perhaps as a studio step that L3.1b's routes feed.

### 3. ADR-126 derived (ADR-126 A2)
- A case's packs are its dataset's live model's packs. A composite's are its own model's, a superset of its members' (the superset check).
- The case setting becomes read-only, and `PATCH` of a case's packs is refused.
- `investigations.domains` is no longer read, but is kept as a record and marked deprecated in spec 01 (question 3, below).
- Tests (A2): packs equal the model's, red with the stored column read instead; the PATCH is refused; a *Make live* adding FIBO brings the KYC figures to every case on the dataset.

### 4. The home case and *Make live*'s owner step (ADR-145 A4 decisions 2–5 and 7; ADR-140 A9 decision 5)
- **The first *Make live*** in an environment:
  - asks *Who answers for this dataset?*, with the maker proposed first;
  - is refused with no owner, with a service account, and against the System setting;
  - then makes the home case: named for the dataset, of its unit, with the owners as its Authors. Audited.
- **A home case cannot be removed** while its dataset exists: `remove_case` refuses, in words.
- **`scripts.make_home_cases`** gives every existing dataset its home case. It works like the L3.1 migration:
  - a snapshot read and a `DryRun` store, so the dry run writes nothing, shown at its real call site;
  - it names and counts what it makes;
  - a second run changes nothing.
  - Its Author is the dataset's `created_by`, named in the output. A service account, a disabled account or a gone one gives no Author: the case is named and counted as "needs an owner" (question 1, below).
- **A composite and a drawn dataset each get a home case; an analyst layer never does** (question 2, below).
- **Team owners** wait on L2.5: their members are Authors while in the team and not after, red with membership read once.
- **Admin › System's setting** is the screen half of L2.4 part 2 (Lane 2). L3.1b builds the setting's store, route and check.

### 5. The `drawn` dataset kind (ADR-143 A2 decision 5; ADR-140 A9 decision 2)
- `datasets.kind = drawn`:
  - no pipeline loads into it (refused at the Studio's load routes);
  - no rule runs on it until it is merged;
  - no other case reads it unless its Author shares it.
- *New drawing board* with no case makes three things in one step: the drawn dataset (with a starter pack or bare POLE), its home case with the analyst as Author, and the board.
  - **The board is L3.3's.** L3.1b builds the dataset and home-case half, plus an empty board record, if L3.3 isn't merged first.
- The marking ceiling is set by its maker within their clearance (A2 decision 3).
- Listed with a *Drawn* badge: in the Studio (Lane 1's screen) and in Admin › Datasets (L2.4 part 2's).
- **Merging a drawn dataset** (A2 decisions 6–7) is L3.9's, not L3.1b's.

### 6. *Domain model* wording (ADR-140 A9 decision 1)
- `tools/ui_words_check.py`: no screen string says "target model". Shown red with a planted string, then wired into `make ci` by the orchestrator (the Makefile is protected).

## Tests to name now (rule 12)

- **Store:** one live, at most one draft; N+2.
- **Pipelines:** a running pipeline is unchanged by an edit; make-live flags exactly the pipelines that write a changed type.
- **Packs:** derived; the PATCH refused.
- **Make live:** the three refusals; owners become the home case's Authors.
- **Home cases:** exactly one per dataset after `make_home_cases`, its dry run writing nothing; a home case can't be removed.
- **Drawn datasets:** loads and rules refused; read by no other case.
- **Wording:** the UI-words gate.
- **Access:** a test on every new read path (rule 4), and the existence-leak test for each new 404 (rule 3).
- **Keyboard and axe** (dark, light, GOV.UK) for *Make live*'s owner step and the Model tab, in whichever lane owns the screen.

## The four questions, settled (the orchestrator's recommendation, 8 November 2026, listed for the owner)

1. **An existing dataset's home case takes its `created_by` as Author,** named in the output. Where `created_by` is a service account, disabled or gone, the home case gets no Author. It is named and counted as "needs an owner", flagged for Admin › Datasets' *Change owner…*, and nobody is made Author by default (ADR-112 Amendment 5: service accounts own nothing).
2. **A composite gets a home case, and so does a drawn dataset** (at its making, ADR-143 Amendment 2 decision 5). An analyst layer never does.
3. **`investigations.domains` is kept as a record:** no drop in L3.1b, and the column is marked deprecated in spec 01. Dropping it is a later step's decision, with its own migration.
4. **One home case per dataset per deployment,** until releases bring a second environment. This is stated in the ADR text L3.1b writes, as the reading of ADR-145 Amendment 4 decision 5.
