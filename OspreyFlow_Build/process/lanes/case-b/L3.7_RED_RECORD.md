Reproducible: `plants_L3.7.py` in this folder (`--live` for the store plants, under a lease). Each
plant is an exact-string replacement asserted to occur once, at the call site the test reaches; the
file is put back after its run, and the suite is green before and after.

Two plants went red by a path other than the one first claimed (rule 15's second paragraph):
- With the deployment-scheme guard removed, `test_a_mapping_from_another_scheme_than_the_deployments_is_refused`
  first stayed green, because its items were in 5x5x5 and the item-in-another-scheme check refused
  the same input for its own reason. The test now draws its item in the mapping's own old scheme and
  asserts the guard's words.
- Removing the withdrawn filter does not regrade a withdrawn item: the store (and the fake) gives
  back no withdrawn (reverted) element, so the item counts as unread and the change is refused
  whole. The row is titled for what it shows. The registry's own SQL filter is the live row.

The lane review found the command's adapter given no ontology (every real write refused) while
every test passed. The live test had built its own adapter with one applied. The live test now goes
through the command's own `graded_items`, and the first live row is that plant.
