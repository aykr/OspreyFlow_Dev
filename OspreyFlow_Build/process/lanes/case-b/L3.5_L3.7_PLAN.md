## L3.5 — analyst-defined link types, decided on the Studio's Model tab

Files: `services/api/link_types.py`, `link_type_store.py`; `app.py` (routes, ratified at merge);
`apps/workspace/src/linktypes/**` (the proposals block `ModelProposals.tsx`, the API client);
one mount line in `ingest/studio/ModelTab.tsx` / `IngestStudio.tsx` (studio's; lines in the report).

1. A pending type is offered only in the case it was proposed in (ADR-090 Am 4 "within the case");
   no other case reading the same dataset sees it, by the offer, the withdrawal or the name check.
2. A new status `accepted`: a holder of `accept_types` past the dataset's gate *Adds it to the
   draft model* (a `link_type` extension in the draft, opened if none) or *Declines* it (`rejected`,
   with a reason). Same-name proposals of the dataset that fit are merged into the accepted one.
3. `promotion_refusals(case, principal, names, dataset)`: a type pending, declined or withdrawn is
   refused with its reason; accepted but its model version not yet live, refused naming the
   version; live, allowed. Route `POST /v1/investigations/{id}/link-types/promotable` is its first
   call site (L3.4's sheet calls the same function).
4. The admin promote/reject routes refuse a proposal that names a dataset (decided on the Model tab).
5. A name in the dataset's model (live or draft) is refused at proposal.

Tests first, each red by a plant at its real call site (`L3.5_L3.7_RED_RECORD.md`):
`test_a_proposed_types_links_are_refused_promotion_then_allowed_once_accepted_and_live` (route),
`test_a_proposed_type_is_visible_only_in_its_own_case` (service and route; rule 3),
the Model-tab routes' access tests (404 outside the dataset, 403 without `accept_types`),
`test_route_rights.py` rows; Vitest for the block; keyboard case in `keyboard/` (rule 13); axe in
dark, light and GOV.UK.

## L3.7 — the grading scheme setting and its change command

Against lane/case's `Grading` shape (no second definition), behind a small port of graded items.
`grading.scheme` in the deployment settings, shown read-only in Admin (request); the command
`ospreyflow grading change --to <scheme> --mapping <file> [--dry-run]` as `scripts.grading_change`:
counts per mapping, then rewrites each grade keeping the original and its scheme, audited.
Tests: the dry run writes nothing (red with a write planted); every item keeps its original;
an unmapped grade refuses the whole change before anything is written.

## L3.7, as built on main with L3.3 (9 November 2026)

Grades live in each drawn element's `provenance.drawn.grading` (L3.3); `Boards.edit` rewrites one in
place by upserting under the same id. So:

1. `schemas/domain.py`: `DrawnAssertion.original_grading`, the grade and scheme an item had before
   its first change of scheme, kept for good (its own commit at the head of the branch, with the
   generated types).
2. The setting: `grading.scheme` in `osprey.yaml` (`schemas/deployment.py`), from `install.yaml`'s
   `grading.scheme` (`cli/ospreyflow/answers.py`), rendered as `OSPREY_GRADING_SCHEME`
   (`harness/render.py`), read by the Conduit (`config.GradingSettings`), answered at
   `GET /v1/grading-scheme` for Admin's read-only display and the boards (carried to admin and case).
3. `services/api/grading.py`: the mapping file (every grade of each part of the old scheme to one of
   the new), the plan (how many items each mapping line moves), and the change over a port of graded
   items; refused whole, before anything is written, for a mapping that does not cover the old scheme,
   an item in another scheme, or a registered item that cannot be read back (rule 2).
4. `scripts/grading_change.py` (`python -m scripts.grading_change --to <scheme> --mapping <file>
   [--dry-run] --changed-by <you>`): the operator command; the port over the board registry and the
   graph; writes the new scheme into `osprey.yaml` and an audit record. Run with the Conduit quiet,
   as `revert_load` is.

Tests first: `test_grading_change.py` — the dry run writes nothing (red with a write planted at the
dry-run branch), every item keeps its original grade and scheme (red with the original overwritten
at a second change), an incomplete mapping and an item in another scheme refused whole before any
write, an unread item refused whole; the setting rendered, read fail-closed and answered; each red by
a plant at its call site.
