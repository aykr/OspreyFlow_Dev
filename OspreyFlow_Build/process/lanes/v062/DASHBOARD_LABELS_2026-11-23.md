## Added at 11:45 UTC on 23 November (the owner: "the dashboard is not reflecting the true picture")

The data was fresh (`status.js` updated 11:40:54). **The picture was wrong in these places, all from the same cause: one entry per build, from one slice, read from records that lag.**

| # | What the dashboard showed | What was true | Cause |
| --- | --- | --- | --- |
| 9 | **No merge running.** DC1 shown as "done". | **DC1b was merging**, step 5 of 7, since 11:12. | The build's entry is its latest-merged slice (DC1c, merged); the merging slice is another slice of the same build and is never read. |
| 10 | PL12 "Stopped: refused by the gate: 0 tests; resume.py send-back returns it to the builder". | PL12b is **verified** (round 6); its server run for a fresh result is running. The "refusal" came from the line's own rerun running `make test-js` in the wrong folder (no such target there); every suite passed. | A refusal is shown as stopped whatever its cause (see item 5), and the rerun's own fault is shown as the part's. |
| 11 | SE9 "Stopped" (the Docker-disk refusal of 06:12). | SE9 is **verified**; its last server run was green alone and red once on a known flaky test; it waits for a server slot. | The same item 5: the old refusal is never cleared by the later facts. |
| 12 | IS2 "checks green; verifier pending". | IS2a is **verified, accepted narrower** on the owner's standing line (11:22), and waits for the server. | The board reads `verify-<tip>.json` with verdict "pass" only; "accepted narrower" has its own record (`accepted-<tip>.json`) that this view does not read. |
| 13 | PL7 "checks green; verifier pending" for PL7a2b; PL7c invisible. | PL7a2b's verifier started at 11:36, PL7c's at 11:42 (it was in round 3); the box has no running-seat signal (item 2). | One entry for two slices of the build, and no running-seat record. |
| 14 | AD1 shows AD1b only. | AD1a, verified, also waits (behind AD1b, back to back). | One entry per build (item 8). |

**What would make the picture true:** the dashboard lists **every cut slice that has not merged, one row each**, with its own state, from records read in this order: a merge record (merged), a merge progress record (merging, with the step), an `accepted` or `pass` verifier record (verified), a running-seat record (building or verifying), a stop or refusal record, with the refusal's cause in words. A build is then the count of its slices.

**The conductor's own change, not the line's:** none of this is a fault in `slices.tsv`. The SE8d row is removed in the next records commit so the dashboard stops listing it; that does not fix the missing "retired" state.
