# Line faults found overnight (20 to 21 November): for the once-a-day fix batch, not fixed in place

1. **The line's own tests straddle midnight UTC.** LR1's merge (second attempt, started at 23:4x UTC on 20 November) was refused by `make -k ci` at `slice-line-check`: five tests in `OspreyFlow_Build/scripts/slice_line/tests` failed with `Refused: no line 'S1<TAB>add-round<TAB>2026-11-21' ... (the owner's word, today, UTC)`: `test_send_back.py::test_send_back_past_the_rounds_limit_needs_the_owners_add_round_line`, and four in `test_seat_failure.py` (`test_undo_seat_failure_gives_co2_its_round_back_on_the_owners_line`, `test_clear_account_removes_the_stop_only_when_the_probe_is_accepted_and_logs_it`, `test_clear_account_keeps_the_stop_when_the_probe_is_refused[refused]`, `test_clear_account_refuses_an_account_not_stopped_or_not_the_owners`). Each writes a line dated with a `TODAY` taken once, then runs a script that reads "today" again; a run that crosses 00:00 UTC (the suite takes about 7 minutes) writes yesterday's date and is refused. Fix: take the date once and pass it to the script, or freeze the clock in the test. This is a once-a-day line-fix row; the merge was simply retried after midnight.

The cause was not found; they are named so the same two failing again becomes a stop under the line's rule.
3. **A `git status` change in the main checkout blocks a merge, and tracked files in `process/lanes/v062` that the conductor edits count** (the morning hold list was edited while a merge needed a clean tree). The conductor commits such edits with `records` before starting a merge.
