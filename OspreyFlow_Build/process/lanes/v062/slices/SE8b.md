## What (in this order; each a test red first, a planted fault at the shape the code really sees: rule 15)

1. **Find every route that sends data out of the product, by search, and write the list.** Every route or function that returns a downloadable artefact or a body the caller keeps as an export: reports, assessments, packs, feeds, CSV or file downloads, dataset releases, rule files, source file reads, backups, anything that streams a stored object, and every connector or job that pushes data to another system. For each: path, function, who, whether it has a case, whether it writes a ledger row now, and **for each you do not change, why** (the owner's rule is "any export route writes a row"; a route that is not an export must be argued so, not skipped).
2. **The ledger accepts an export with no case.** Make `investigation_id` nullable (a migration in the pattern `export.py` already uses; a migration test; existing rows unchanged) **and add what the row needs to say what the export concerns:** a `subject_kind` (`dataset`, `rule`, `report` and so on) and `subject_id` (the dataset or rule it concerns), both set on every new row (for a case export the subject is the case's artefact as today; do not break the existing reads, the role-gated read, or the existing tests). Who reads a no-case row: the same role-gated read as every row; say in your report how a person who may not see the dataset is kept from learning that a release of it exists (rule 3 and 7: no oracle; the ledger read must not reveal a dataset the reader has no right to).
3. **The dataset release, the rule file and the case-report read write a ledger row** (and keep their audit row): who, when, kind, subject, item count (the count of what was actually exported, never the stored count of what the reader may not see: the rule SE7 set), handling level where the export has one (a dataset release carries the dataset's handling; read how the release is built and name the field; if it has none, record that it has none and say so), the withheld flag as the route computes it. The row is written **before** the artefact is returned and a failure of the ledger write fails the export closed (as the audit writer does: `AuditWriteError`, 503), with a test.
4. **The backup and any object transfer:** decide from the list in item 1. A platform backup is an operator's act on the whole deployment: record it in the ledger as an export of kind `backup` with the operator as principal and no case, **unless** you find it runs outside the Conduit's reach (`harness/backup.py` is the CLI, not the Conduit): then say so, write the smallest change that records it where the product can (for example the Conduit's `platform_backup.py` writing the row when it takes the backup) and list what cannot be recorded by the Conduit in your report for the owner. Do not make the CLI call the database.
5. **The report feed's `withheld=False` (about 14822).** Read what the feed can contain. If the figures can be withheld (a count lowered by the reader's rights), the hard-coded `False` is a false record: fix it with the real flag and a test (planted: the old constant; red). If they cannot, say why in your report and make the constant a named one with a test that the feed's items never carry a withheld figure.
6. **The completeness test (rule 12).** A test that fails if an export route writes no row: an AST scan of `services/api` that names every route handler that returns an export (by a reviewed list in the test, each entry with the reason, plus a search for return types and response classes that stream a file) against the handlers that call the ledger writer, with a planted new export route (red) and a planted route that drops its ledger write (red); and a per-route test through the test client with the fake store that asserts a row exists with who, kind and subject. **Say which folders the scan walks** (a scan row is written from that). This is also the first step of SE8d (the completeness gate over every route): build the scan so SE8d can extend it to model calls and sign-ins; say how.
7. **Never in a row:** any content of the export, any key, token or address. Names and ids only; a synthetic secret placed in a dataset's name or metadata at run time never appears in the ledger row beyond the name the person gave (the test asserts it is stored as a name only if the route stores names at all: prefer ids).
8. **Report:** the list of item 1 with what you changed and what you left and why; the schema change and its migration; the read rule for no-case rows; the feed finding; what SE8c and SE8d must cover.
