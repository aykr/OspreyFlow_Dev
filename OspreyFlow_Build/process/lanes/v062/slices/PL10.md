- **Dial setting:** balanced

- **After:** nothing (PL3 and CO3 are on main). Runs beside PL4 and PL9.
- **Status of this brief:** written by the conductor on 20 November 2026 under the owner's standing approval, from a read-only scout of the

## What

`OspreyFlow_Core/apps/pages` holds the person's session (access token on the server, a signed cookie, a synchroniser CSRF token, a strict
CSP) and forwards one thing to the Conduit: the WebSocket stream (CO3, `server/stream.ts`). Nothing forwards ordinary `/v1` HTTP calls, so a
page cannot read or write anything. Today the workspace's nginx does it (`apps/workspace/nginx.conf.template`, `location /v1/`). This slice adds
the forwarder to `apps/pages`, mounted through `extraRoutes` in `server/app.ts` so it sits behind the same headers, session and CSRF. Read
`server/sessionPolicy.ts`, `csrf.ts`, `headers.ts`, `config.ts`, `stream.ts` and `test/server/stream.test.ts` first; reuse their shape.

Choices, **settled by the conductor**:
1. **Which paths:** every path under `/v1/` **except** a deny-list: the stream (CO3 owns it), `/v1/ws-ticket` (pointless once pages holds the bearer) and
   any path that is not under `/v1/`. The Conduit authorises each route (rules 3 and 4); the forwarder adds no access rule of its own. **Path hygiene
   first:** match the raw path before any decoding or normalising; refuse (404, in words) a path holding `%2e`, `%2f`, `%5c`, a backslash, `..`, a double
   slash or a NUL; never follow a redirect; the upstream host is `OSPREY_PAGES_CONDUIT_URL` and nothing else (it is already scheme, host and port only).
2. **What is sent upstream:** the method, the path **and the query string** (routes need `?name=` and the like; the stream drops it, this does not), a
   body, and exactly these headers: `Authorization: Bearer <the session's access token>`, `Content-Type`, `Accept`, `Content-Length` recomputed, and
   `X-Request-Id` if the browser sent one of reasonable length. **Nothing else the browser sent**: not its `Cookie`, `Authorization`, `Origin`,
   `X-Forwarded-*`, `X-CSRF-Token` or `Host`. Add `X-Forwarded-Proto` and `X-Forwarded-For` as nginx does today.
3. **The session and the token:** one function in one module, `accessTokenFor(session)`, returns the bearer. Today it returns the session's access token.
   **PL9 (the real sign-in) replaces its body with the renewal**; build the call sites to await it. A request with no session, or an ended one, is
   answered `401` with the Conduit's body shape `{"detail": "..."}` in words, and **the Conduit is not contacted** (a counter in the test's fake proves it).
4. **Anti-forgery:** the existing synchroniser check covers every method but `GET`, `HEAD` and `OPTIONS`; the token is read from the `X-CSRF-Token` header. A refusal
   on a `/v1` path is JSON `{"detail": "..."}` with 403 (the existing HTML page stays for page routes). Multipart bodies carry the token **in the header only**
   (the form-body field cannot be read from a multipart body). The token reaches a script through a `<meta name="csrf-token">` in `views/layout.njk`
   (rendered from the session's token; CSP allows it) and for forms through `res.locals`. No endpoint returns it. No `Origin` check on HTTP: CSRF is the guard
   (the Conduit checks no Origin on HTTP and a server-to-server call sends none); say so in a comment.
5. **Bodies:** JSON and other small bodies are read whole under a cap; the default is `OSPREY_PAGES_BODY_MAX_BYTES` = 32 MiB. **Raw uploads stream** upstream
   (never buffered whole) under `OSPREY_PAGES_UPLOAD_MAX_BYTES`, default 512 MiB, the Conduit's own default (`OSPREY_INGEST_MAX_UPLOAD_BYTES`); a declared
   `Content-Length` over the cap is refused before a byte is read, and a stream that runs past it is cut: **413** with the Conduit's wording ("That file is larger
   than the upload limit."). Both settings are validated by `config.ts` in words (a whole number of at least 1; the service refuses to start otherwise).
6. **A browser form upload (scripts off):** a `multipart/form-data` post to a **raw-body upload route** (the five the scout found: ingest source-files, a board
   node picture, a node picture, a document, rules import; the route table is the allow-list for this translation only) is read by the page service, which takes the
   file part and forwards its bytes **raw**, with the file's name as `?name=` and the other form fields as the route's query fields; the Conduit stays unchanged
   (ADR-152 F1). Use a streaming multipart parser (a new dependency must pass `make licence-check` and be entered in `OspreyFlow_Build/spec/00_ARCHITECTURE.md`
   section 7 before use). A multipart post to **any other** route is refused 415, in words. **The Conduit's one multipart route, `/v1/investigations/{id}/sites`,
   is not carried in this slice** (the owner's ruling is needed: "multipart in, raw out" does not fit a route that takes multipart); a backlog row is the conductor's.
7. **Responses:** the status, the body **streamed through, never buffered** (so tiles, PDFs and the server-sent basemap build work), and only these headers copied
   back: `Content-Type`, `Content-Disposition`, `X-Guide-Version`. Everything is `Cache-Control: no-store` (the existing rule). **Pass the Conduit's `401`, `403`, `413`,
   `422` and the like through unchanged**, body included (the Glass reads `detail`): a Conduit `401` does **not** end the pages session in this slice (PL9's renewal
   decides). Never pass a `Location` header.
8. **Failure words:** the Conduit cannot be reached or refuses the connection: `502` `{"detail": "..."}`; no answer within `OSPREY_PAGES_UPSTREAM_TIMEOUT_SECONDS`
   (default 3600, nginx's hour for a long read; at least 1): `504`. Node's own server timeouts must not cut a long upload or a long read short: set them explicitly and
   test one slow body. The Conduit's address setting is lifted out of the stream's settings so HTTP does not depend on `OSPREY_PAGES_PUBLIC_ORIGIN`; with
   `OSPREY_PAGES_CONDUIT_URL` unset the forwarder is absent (every `/v1` path answers 404, as PL3's tests expect).
9. **Secrets:** no token, cookie or session id appears in any response, header, log or error (a generated sentinel, as `secretLeak.test.ts` does; the secret rules
   hold: no fixed key-shaped string in any file, test values generated at run time, the service refuses to start in words and never prints a secret).
   Log only a fixed phrase and a status.

Binding: process/CLAUDE.md rules 3, 4, 11, 12, 15; spec/06_DECISIONS.md ADR-152 decisions 3 to 5, F1; the PL3 and CO3 briefs' secret rules; British English.
If something here turns out to need a Conduit change, **stop and say**.

## Acceptance test

One new file, `OspreyFlow_Core/apps/pages/test/server/forward.test.ts`, with a **fake HTTP Conduit that refuses what the real one refuses** (rule 15): no or bad
bearer: `401` `{"detail"}`; a raw upload route over the cap: `413` with the wording above; a missing `name`: `422`; **no** content-type refusal on the raw
routes (the real Conduit does not check it; a fake stricter than the real one would mislead); a bearer in the URL ignored; it records every request (method, path,
query, every header, the body's length and a hash) and counts connections. Cases, each planted at the real call site (a real HTTP request through the app's server,
a `fetch` or the test kit's client with a signed session cookie), each shown **red** before the code and for its own reason:
- a request with a session reaches the fake with exactly one `Authorization: Bearer <that session's token>` and **none of the browser's** `Cookie`, `Authorization`,
  `Origin`, `X-Forwarded-*`, `X-CSRF-Token` (planted: a forwarder that copies headers); the path and the query string arrive as sent; two people's sessions reach
  their own tokens, never each other's; no session or an ended one: `401` and the fake sees **no connection at all**;
- a state-changing request without the CSRF header: `403` JSON, fake untouched; `GET` needs none; a multipart post carries it in the header only;
- path hygiene: `%2e%2e`, `%2f`, `..`, a double slash, a backslash, a path off `/v1/`, the stream path and `/v1/ws-ticket`: each refused, fake untouched;
- JSON round trip and the Conduit's `401`/`403`/`422` bodies passed through unchanged; a `Location` from the fake is not passed; a redirect from the fake is not followed;
- raw upload: bytes arrive intact (hash), streamed (the fake sees data before the client finishes: planted: a forwarder that buffers), a declared length over the cap is
  refused before any byte is read, a stream past the cap is cut with `413`; the browser's multipart form post to a raw route arrives as raw bytes with `?name=` from the file
  part (planted: a forwarder that sends the multipart envelope on), and multipart to another route is `415`;
- response streaming (a large body and a server-sent body arrive in pieces) and the three copied headers only;
- Conduit down: `502`; slow upstream past the timeout: `504`; a long slow body is not cut by Node's timeouts;
- the token, cookie and session id appear nowhere in any response, header, log, stdout or stderr (generated sentinels);
- the service refuses to start in words for a bad cap or timeout, and with `OSPREY_PAGES_CONDUIT_URL` unset every `/v1` path answers `404`.
State in the file's header which test fails if the forwarder were to leak a header or buffer an upload (rule 12).

## Round 2 (20 November 2026): what the first verifier found, and the rulings

The round-1 verifier found four faults at tip 64f462ba90. Fix those and nothing else. The owner's additions to the conductor's rulings are in force.

1. **The path, canonically (the owner's ruling, replacing item 1's matching).** Take the raw path (the part before `?`), **percent-decode it exactly once**, and resolve it to **one canonical form**.
   Refuse (404, in words, the Conduit not contacted) anything that is **still encoded after that one pass** (a double-encoded character: a `%` followed by two hex digits left in the decoded
   path), an **encoded slash, backslash or dot** (`%2f`, `%5c`, `%2e`, in any hex case), a **dot segment** (`.` or `..`, literal or decoded), a **path parameter** (`;`), a double slash,
   a NUL, CR or LF, and any path that does not start with exactly `/v1/`. **Match the deny-list on the canonical form** (the stream `/v1/investigations/{id}/stream` and `/v1/ws-ticket`,
   with or without a trailing slash, in any case: the Conduit is case-sensitive, but refuse the deny-listed names whatever their case), and **forward the canonical form** (re-encode
   only what a path needs, by one fixed rule), so what was checked is exactly what the Conduit receives. Tests, each **red first**: `/v1/ws-t%69cket`, a double-encoded letter
   (`%2569`), mixed-case hex (`%2F`, `%2f`, `%6F`), a mixed-case path (`/v1/Ws-Ticket`, `/V1/...`), a trailing slash, a dot segment, a `;` parameter.
2. **The query is not path.** The hygiene refusal covers the path only. The query string arrives **as sent** (an encoded `/`, `.` or `\` in a value is legitimate: `legal_basis=IPA%202016%20s.61%2F62`),
   refusing only a raw NUL, CR or LF in it. Test: that exact request reaches the fake with the query intact.
3. **`_csrf` is never forwarded and never appears in any URL or log.** Three cases, one test each, red first: (a) the header `X-CSRF-Token` (not sent upstream: already so);
   (b) a url-encoded form body carrying `_csrf` (the field is removed from what is forwarded; the rest of the body is unchanged); (c) a multipart form carrying `_csrf` (**the first part** of
   the body; **checked before any file byte is read**, so a wrong or missing token is refused 403 without reading the file; never copied into the upstream query or body). The verifier
   also found a gap in the brief: a scripts-off browser form cannot set a header, so the header could not be the only accepted place for a multipart post. **A multipart post carries the token
   as its first part (or in the header); a url-encoded form carries it as the `_csrf` field; the header is also accepted.** No test or log line may show the token's value (generated sentinels).
4. **The public origin (the owner: the ruling stands this round).** The forwarder is mounted only when `OSPREY_PAGES_CONDUIT_URL` is set, **and CO3's start refusal stays**: with the Conduit address
   set and no `OSPREY_PAGES_PUBLIC_ORIGIN` the service refuses to start, in words, as CO3's test holds. Item 8 of the brief is corrected to this: the forwarder does not use the origin itself (HTTP has no
   origin check; CSRF is the guard); it requires it only because CO3's refusal ties the two. **The owner has ruled to decouple them in a small slice after this one merges** (a backlog row); not this round.
   Do not change `streamSettings`' refusal.
5. **Why a deny-list (one line, for the record):** nginx's `location /v1/` passes every route today, the Conduit authorises each route itself (rules 3 and 4), so pages adds no exposure; the only two
   routes pages must never carry are the two that put a credential in the browser (the stream, CO3's, and `ws-ticket`); an allow-list would make every page build edit one shared list. The owner
   accepted this on 20 November.
