## Round 2 (the conductor, 24 November 2026, 06:25 UTC): the upper limits, from the live layout, and the test through the attach path

**The round-1 verifier found one fault and one gap.** (1) **Fault: the store and the attach function do not hold the upper limits the spec table says the pages' frame keeps.** `setTimelineHeight` and `setPanelHeight` apply no upper limit when no `maxPx` is given (`panelFrameStore.ts` about lines 258 and 262), `setSideWidth` stops only at 480 with no canvas room kept, and the only source of a limit is `data-max` read from static markup (`panelFrameAttach.ts` about line 176), which a server-rendered page cannot keep current when the window is resized: repeated ArrowUp on the timeline sash grows the stored height without limit and writes it to `ospreyflow.layout-sizes`, where it survives a reload. The spec's table (which this slice added, about lines 399 to 401 of `spec/02`) says: the timeline held between 96 px and **seven tenths of the window**; the column between 300 and 480 **and leaving the canvas 320**. The workspace computes both from the live layout at each key press (`apps/workspace/src/layout/PanelFrames.tsx` about lines 186 to 188 `tallestTimeline()` and 44 to 48 `widestSide()`). **Do this:** the store (or the attach, one place) **computes the upper limits itself at each resize from the live window and work area, through one injectable function** (the default reads `window.innerHeight` and the work area's width as `sidePanelState.isWide()` reads `window.innerWidth`; tests pass their own), **so no call can omit them; an explicit `maxPx` may only lower the limit, never lift it.** The stored value is clamped on read too (a stored value above today's limit is brought down, a corrupt one ignored). (2) **Gap:** no attach test gives a sash a `data-max`, and none runs the keyboard path against an upper limit. **Add: through the attach path with the viewport function stubbed, repeated ArrowUp on the timeline sash stops at seven tenths of the window and the stored value never exceeds it; the same for the column and the 320 px of canvas; a shrinking window brings a stored size down on the next key press or on read. Red first, planted: remove the clamp from the keyboard path and the case is red.** Nothing else.
