# DOC1a: the truth check of the platform's stated intent (the report for the owner, 20 November 2026)

Made by eight read-only scouts from main on 20 November 2026; the conductor checked one thing itself: **every file the verdicts rest on is identical in release v0.6.1 and on main** (git diff of the tag v0.6.1 against main: the licence gate, the Superset configuration, the egress test and renderer, the audit, assessment and export code, the websites' builder and the architecture guide are all unchanged), so a verdict below holds for v0.6.1 and for main alike unless it says "main only". The security builds SE1 to SE4 are main only. Everything is "read, not measured" except where a line says "measured"; **nothing was measured in a browser yet** (the stack slot the owner pre-approved is scheduled; its result is added to this report). No client, competitor or partner is named. No wording is proposed for the paragraph.

## Constraint 1 in detail

- **The gate:** the allowlist is in spec/00_ARCHITECTURE.md section 7; the Python half reads package metadata from the build environment only (Makefile line 14), so per-image Python sets are gated only for the NER and Laurium images. The Python allowlist has no spelling for OFL-1.1 or Python-2.0 although the spec allows both (the Node half has OFL). Four packages sit on recorded LGPL exceptions (deepparse, psycopg2-binary, gensim, poutyne).
- **GDS Transport (not a gap, the owner's ruling of 20 November; the facts kept for PL7 and AD4):** stated in spec/00 section 7 and ADR-132. Four font files in apps/workspace/public/assets/govuk/fonts; named in the GOV.UK block of packages/design/tokens.css. The gate does not list or exempt it (govuk-frontend passes as MIT by package metadata). Tests hold only that the OspreyFlow brand never fetches the GOV.UK stylesheet (brand.test.tsx) and that the OspreyFlow sign-in has no GOV.UK assets. **Nothing holds "served only under the GOV.UK brand, only on a gov.uk address":** the govuk_identity switch is named in the specification and not yet in code, and the four proof pieces ADR-152 names for I9 do not exist. The host check (brand.ts) gates the crown and footer, not the font.
- **Model weights in a default install (local-lite):** three Ollama models (a 0.5B Qwen instruct model, an all-minilm 22M embedding model, a moondream 1.8B vision model) pulled on every start; a Whisper tiny English speech model fetched on start; Stanza English models baked into the NER image at build; the extraction default Qwen 7B or 14B is recorded as Apache-2.0. **The repository states a licence for none of the first three, nor for the Whisper or Stanza weights** (the software around them is MIT or Apache-2.0). Whether each is open source is therefore "cannot tell from the repository"; the weights are outside the gate.
- **Map data:** OpenStreetMap-derived tier 1 (ODbL), tier 2 OS OpenData (OGL), tier 3 not redistributable; Noto Sans glyphs SIL OFL; Natural Earth not located. None is inside the gate.
- **Other default components:** Apache-2.0 for Superset, Keycloak, OpenSearch, SeaweedFS, Caddy and ClickHouse; the PostgreSQL licence; Valkey BSD-3; LiteLLM "MIT core" (an enterprise folder in the image: cannot tell). **Not stated in the repository: ArcadeDB and Ollama.** The Conduit image carries a Temurin Java runtime (GPL-2.0 with the Classpath exception, admitted by the gate; PL2a carries its notice). The specification's vault table still lists MinIO (AGPL-3.0) as the object store; the generated install uses SeaweedFS (a stale table).
- **Not dependencies but named for completeness:** OpenSanctions (CC BY-NC) and the UN list are synthetic-only; PaySim (CC BY-SA 4.0) and the Enron corpus are optional user-obtained downloads.

## Constraint 2 in detail

- **Network:** the osprey network is internal; only the proxy publishes a port; the default outward set is the proxy, ollama-models and whisper-models. Routes open only by configuration: the model gateway with a hosted provider, Keycloak with mail or organisation sign-in, the Conduit with managed Postgres, an object store, media or an HTTP map source. The held test for "never outside" covers models and mail only. The Kubernetes policies are tested per workload. **No test of the Glass's own browser traffic.**
- **Superset (the owner's finding), read:** the Content Security Policy in deploy/superset/superset_config.py (lines 238 to 254) keeps Superset's as shipped and allows images from two scarf.sh addresses and connections to two mapbox.com addresses. **The repository does not switch Superset's usage tracking off** (no SCARF_ANALYTICS setting, no Mapbox setting, none in the Dockerfile); it is blocked only by the network (Superset has no route out by default). No test covers the policy. Whether the shipped Superset page actually emits the request is not in the repository: **read, not measured; the browser measurement is pending.**
- **Other components (usage reports and update checks):** ArcadeDB, ClickHouse, OpenSearch, Postgres, Valkey, Keycloak and Ollama have no telemetry or update-check setting in the repository; they are only blocked by network placement. The model gateway's cost-map fetch is switched off. The speech server runs with the Hugging Face hub offline, but **its download step does not**. **Ollama's model pull and the speech model download run on every start and reach outside.** The Conduit's transformers recogniser fetches its model from the hub on first use if chosen; Nominatim geocoding only when an administrator sets it. The update check is run by an administrator from the host.
- **First install with no internet:** **not yet** (Lite): install.sh needs uv, git and PyPI; the images are pulled from the registry; the models are fetched on first start; the basemap is an operator step. The offline bundle carries manifests, schema, documents and images, not model weights, basemap tiles or packages; its exit test proves install from the bundle alone, not with networking off, and is opt-in. The update bundle is for updates (update --from; no-network tests). Not measured.
- **The certificate:** the default public address is plain HTTP and fetches nothing. A Small deployment on an https address fetches a certificate by default (Caddy's automatic HTTPS: the domain, the account and the challenge leave; OCSP not disabled); the administrator's choice of an https address is the only switch; a given certificate (network.tls) turns it off. No test asserts the default fetch's outward calls.
- **Front ends:** the Glass, pages and install page reference no external address; the map style default points at a public tile server but the bundled style overrides it; the pages service has a strict Content Security Policy (tested); the Glass and front proxy set none.

## Constraint 4 in detail (the three statements, reconciled)

- **Scale:** 429 route decorators, about 300 audit call sites; no test maps routes to audit calls (test_audit_kinds checks that every written action is classified, not that every route writes one).
- **Unaudited by design (read):** deployment metadata (the ontology, map providers, ingest connectors, packs and transforms, tile proxy) and several case reads (link types, promotable, link history, case brief); the export ledger's own listing; **refusals other than case access, connector reads and Studio recipes are not audited** (spec/06 says so; a test says a refused removal is not audited).
- **The store:** audit_log in Postgres (recorded_at, principal_id, action, investigation_id, resolved_query, result_cardinality, justification, org_unit). Append-only in intent only (the database does not yet refuse UPDATE or DELETE from another role); no hash chain. Fails closed (503 on a write failure, tested).
- **Exports:** the export ledger (table export_ledger) records who, when, case, handling level and withheld flag for report and assessment exports, pack exports and the report feed. **Audit row only, no ledger row:** dataset release export, rule file export, source file read. **Neither:** platform backup and object transfer.
- **Model calls:** audit rows for ask, extraction, email extraction, document designation and patterns-ask record the person and the case, but **ask does not record the engine**; the gateway's usage record is per engine and job per day with **no person or case**; transcribe, describe-image and embed leave no audit row; background workers not checked. **No test fails when a model call is not recorded.**
- **Sign-in:** the pages service and the Conduit record no sign-in or session event (the identity provider holds them; not checked).
- **The three statements:** (i) the architecture guide, section 6, "Every read and write is audited, with who, when and what" is **too strong**; (ii) spec/03 section 6, "Every read, expansion, path query, pattern run, document view and export records ..." is **partly true, scoped** (it carves out deployment metadata; it needs a scope note and is silent on model calls and sign-in); (iii) the websites, "every read that was refused", is **too strong** (it is in the animated overview on both homes). The phrase "every access, export and model call must be attributable" appears nowhere in the repository. **The facts the wording must fit:** the unaudited route families above; model calls attributed by gateway counts, not per person; only some exports write a ledger row; refusals audited for case access, not all; sign-in events not recorded by the platform. The correction to the wrong ones is part of DOC1c whatever else is decided.

Not built or not found: a separate uncertainty field beyond the band; an inferred or confirmed status on a judgement; the export of contradicting items was not read. ## Your five points

- **A, "no data or telemetry leaving unless an administrator allows it":** see constraint 2. True by network placement, not by switches; Superset's tracking is not switched off; the models and speech weights are pulled outward on every start. Pending: the browser measurement.
- **B, "every access":** see constraint 4. Not true as written (the unaudited families, model calls, some exports, refusals, sign-in).
- **C, "every dependency under an open-source licence":** see constraint 1. GDS Transport is **not a gap** (the owner, 20 November: it applies only to UK government, which is sovereign over it; keeping it off everywhere else stays with PL7 and AD4); the finding is that model weights, map data, fonts and base images are outside the gate and several weights' licences are stated nowhere.
- **D, "emerged from the source material during design":** **nothing public explains it.** No file in the specification, process records, docs, Core or the marketing site contains the phrase or a source for the constraint; it appears only in the working notes of the owner's outputs folder (the adviser's note says an outside reader cannot tell what the source material is). The nearest public text is a decision-log mention of "a real, well-known case study" that does not explain the constraint. The source material itself is not in the repository.
- **E, the names:** "Privacy control" and "Security management" are **not product terms**. For need-to-know the product says need-to-know, access control, clearance, withheld and handling (about 125 uses across the four guides; the websites: "Need-to-know by design", "Markings and clearance", "Who can see what?"; screens: clearance, withheld). For attribution it says audit, attributable, provenance and accountability (about 83 uses in the guides; "a full audit trail", "Who did what and when", the Admin Audit section). "Sovereign" and "sovereignty" appear nowhere in the product, specification, docs or websites (only in the owner's drafts); the websites say "egress" and "hosted engines, by permission". "Analytical accountability" appears nowhere. "Privacy controls" in the decision log means repository visibility (a clash of meaning, not of use).
