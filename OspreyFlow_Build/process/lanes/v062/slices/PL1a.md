## What

### N05: "The CLI follows the recorded home over the current folder; every command needs OSPREYFLOW_HOME"

`OspreyFlow_Core/cli/ospreyflow/home.py` (`find_product`, about lines 56-80) resolves: `OSPREYFLOW_HOME`, then the recorded home
(`read_recorded_home`, about 28-43), then a walk up from the current folder, else a refusal. That order is what ADR-114 Amendment 3
decision 3, `OspreyFlow_Build/spec/10_ADMINISTRATION_GUIDE.md` about line 305 and ADR-132 Amendment 1 decision 4 say, and **this slice
does not change it**. The fault, read as the owner's "install fault": when the recorded home is a valid product that is **not** the one
the person is standing in, the CLI follows the recorded one **silently** (so a person in a fresh checkout acts on another
deployment's folder), and the recorded home goes stale after a repoint or a reinstall and nothing says so. Choices, **settled by the
conductor**:
1. When the recorded home wins and the walk up from the current folder also finds a product, and the two are different folders, the
   CLI prints one line on standard error before it acts, in words: both folders, that the recorded one is being used, and how to
   choose the other (`OSPREYFLOW_HOME=<folder>`); nothing else about the command changes, and the exit code does not. No line when the
   two are the same, when no product is found from the current folder, or when `OSPREYFLOW_HOME` is set. `doctor`'s tolerance of
   a missing product is unchanged.
2. The installers (`OspreyFlow_Core/install.sh` about line 49 and `install.ps1` about line 58) record the folder they install; read
   them and say in your report what they do on a **second** run. If a reinstall does not re-record, make it re-record the folder it
   installs, with a test that reads the script's own text or runs it against a temporary home (whichever the neighbouring tests
   do); if it already does, change nothing there.
3. If the owner prefers the other reading (the current folder beats the recorded one), that is an amendment to three accepted texts
   and a later slice; do not do it here.

### N06: "A fresh install from a git archive cannot seed demo packs"

`OspreyFlow_Core/scripts/seed_internal.py` refuses, before any per-dataset branch, when neither `repo_root/.git` nor
`repo_root.parent/.git` exists (about lines 620-626; the row's "611" is stale, 611-619 is the real-data acceptance check), for **every**
dataset, the synthetic packs included. ADR-114 Amendment 2 decision 2 groups "the attested checkout" with the real-data checks. A user
repository made by `git archive` has no `.git`, so no demo pack can be seeded. Choices, **settled by the conductor**:
1. The checkout refusal applies to **real and internal datasets only** (a dataset with `real_dataset` set, or one the code treats as
   internal: read the per-dataset branches), exactly as the specification groups it. A **synthetic** pack (hmp, fixture-corp,
   operation-ledger, the others the module names as generated by code) seeds without a `.git`. The refusal's words stay for
   the datasets it still covers.
2. `OspreyFlow_Core/scripts/seed_paysim.py` about lines 86-87 (`_is_checkout` looks only at the developer layout) has the same fault
   in another shape for an air-gapped install; `seed_enron.py` about 73-76 checks both layouts and is the model. Fix `_is_checkout` to
   recognise the user-repository layout the way `seed_enron.py` does, with the smallest seam a test needs. Do **not** exempt PaySim
   from any check its download delivery requires.
3. Any other caller that needs `.git` (the scout lists `write_pid_files.py` about line 35, `harness/update.py`, `harness/release.py`,
   `harness/backup.py`): list each in your report with what it does without `.git`; change none unless it is a seed path.
4. The existing test `OspreyFlow_Build/tests/test_seed_internal.py` about lines 790-793 asserts that `hmp` is refused without `.git`.
   It asserts the old behaviour: change it to assert the new, and add the real and internal cases' refusal as their own tests.

## Acceptance test

- `OspreyFlow_Build/tests/cli/test_home_says_when_recorded_wins.py`: two planted product folders (a product is what
