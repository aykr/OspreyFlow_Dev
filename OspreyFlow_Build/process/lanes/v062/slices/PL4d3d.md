### Round 2: how the declared-units proof lives in the repository (the conductor, after the round-1 verifier found two faults in it)

The round-1 verifier (tip `1310ff3`) found two faults in the proof test, both faults of **my brief** (it said "a pure test that runs `dist_compare` against the baseline" and did not say where the baseline build lives or how long the test lives): **(1)** `test_pl4d3d_declared_units.py` reads a build folder that exists only on the Mac (`~/dev/osprey-acceptance/PL4a-baseline/dist`, or `PL4_BASELINE_DIST`) with a hard `assert`, and it sits in the always-collected `tests/glass_trees`, so GitHub's `test` job and a clean merge tree would error on it, which makes "merge only once GitHub is green on that exact commit" impossible; **(2)** the test always compares against the pre-PL4 build, so after this slice merges, any later change to the built workspace (D3e, slice E, AD1b) would turn `make test` red with an "undeclared difference". **The design that fixes both (the owner's ruling stands; this is how it is built):**
1. **The unit comparison runs only where the baseline build exists, and says so when it does not.** The test **skips with a stated reason** when the baseline folder is absent (GitHub, a clean merge tree): the skip message says "the declared-units proof runs where `PL4_BASELINE_DIST` exists (the builder's and the verifier's Mac)". **It never hard-errors on a missing folder.** A second test, which needs no build and always runs, proves the **declaration file itself** (well-formed lines, each unit named, each reason one of split/new/moved) and that the skip logic itself works (planted: a folder that does not exist skips, a folder that exists does not).
2. **The proof belongs to one baseline and retires itself.** The declared file's first line records `against: <hash of the baseline dist folder it was generated against>`. **The unit comparison runs only if the folder's hash equals that value; otherwise it skips with "this proof belongs to an earlier baseline".** When this slice re-records the baseline at its final commit (the owner's ruling, item 3), the folder holds the new build, the hash no longer matches, and the proof stops running by itself, so later slices are not blocked: **D3e, slice E and AD1b compare against the new baseline** (`dist_compare verify --build`, which compares a recorded hash, as before). A test shows the retirement: a declared file for an older baseline skips and a matching one runs.
3. **The verifier and the builder see it run, not skip.** On the Mac the baseline folder exists and matches until the re-record, so the frozen check runs the comparison; **your report says, in one line, "the units proof ran (n units differ, all declared)" or "skipped, and why"**; a skip in your own final run is a finding for you to fix, not a pass.
4. **Everything else in this brief and the owner's ruling stands** (declared units, re-recorded baseline with a diff listing only declared units, GitHub green on the exact commit, the Playwright count and the checks' reach, the one-line report). Do not edit the frozen checks (a refreeze is the owner's); the row already runs `test_pl4d3d_declared_units.py`.

Anything else declared as knock-on fails the slice. The builder lists each knock-on unit with which of (a) or (b) it meets; the verifier checks each against the rule, not against the builder's word. If the tool cannot normalise names for (b), the verifier shows the diff of each such file and confirms every differing string is a chunk name.* So: the build-free test (the declaration's well-formedness) **enforces** the rule: for a `knock-on` row it requires a third column `(a)` or `(b)`; for `(a)` it reads the file's `git diff main` and fails if any changed line is not an `import` line (or a blank line between imports); for `(b)` it normalises hashed chunk names on both sides of the pair (the name pattern `assets/<stem>-<hash>.<ext>` and every reference to it) and fails unless the two are then byte-identical; where `dist_compare` cannot normalise, the test prints the diff of the file and fails unless every differing string matches the chunk-name pattern.
