## Why it is needed (what no page can do until it lands)

`OspreyFlow_Core/apps/pages/server/accessToken.ts` is a stub: `accessTokenFor(session)` returns the access token the session holds, and its header says "PL9 replaces the body with the renewal". **So today every page that calls the Conduit works only until the access token's life ends (Keycloak's default is a few minutes); after that the Conduit answers 401 and the forwarder passes it on (`forward.ts`: "a Conduit 401 does not end the session here"). No page can be used for longer than that: the Studio pages (IS3, IS5a, IS6a), every GOV.UK page (GR2a Help excepted: it calls nothing; GR3a, AD3a, RM1a) and the panel frame's pages when they mount.** And **sign-out ends only the pages session, not the person's session at the identity provider**, so "signed out" in the pages leaves them signed in at Keycloak (a browser that goes to another Osprey page signs in with no prompt): that is a security rule, the owner's.

## What (in this order; each red first, planted faults at the shape the code really sees: rule 15)

1. **Renewal in `accessTokenFor`** (the forwarder and every call site stay as they are): when the access token is within a margin of its end, exchange the refresh token for a new access token at the provider's token endpoint, **update the session record** (access token, expiry, and the new refresh token when the provider rotates it), and return the new token. **Single flight:** concurrent requests of one session make **one** exchange (the others wait for it); **never two exchanges with the same refresh token** (a rotating provider revokes the family on reuse). **No token, no refresh token and no authorization header is ever logged or put in an error.** The margin is a named constant with a test.
2. **The refused-refresh behaviour.** The provider's refusals (an expired or revoked refresh token, `invalid_grant`, a provider that is unreachable, a response without an access token) **end the session cleanly: the page service destroys the session, clears the cookie and answers the person with the sign-in redirect on a page request and with a plain 401 body on a script or `/v1` request; never a loop of redirects, never the old token sent again.** An unreachable provider is **not** an ended session (a retry with backoff for a short time, then the same as a refusal, say which and why). **Red first against a fake identity provider that models the real one's refusals** (Keycloak's own error bodies and status codes for each case; read how PL9a's fake does it and extend it; a fake that grants everything is the defect this slice exists to avoid).
3. **Sign-out at the provider.** Sign-out sends the person to the provider's end-session endpoint with the id token hint and the registered post-logout redirect, **and** ends the pages session first (so a failed provider call never leaves the pages session alive). **Back-channel logout:** a route that receives the provider's logout token, **validates it fully (signature against the provider's keys, issuer, audience, the logout event claim, no nonce, the `sid` or `sub`, a short age, and replay refusal)** and ends the matching pages sessions; **a token that fails any check ends nothing and answers a plain refusal with no detail**. **Front-channel logout** only if ADR-152 decision 5 or ADR-050 Amendment 4 names it (read them: if neither does, say so and do not build it). **The realm client needs its back-channel logout URL and the post-logout redirect URIs set from the one derived public origin (PL7f's `derive` when it has merged; until then the same value the realm client already uses): the realm file the renderer writes, with a test.**
4. **Not in this slice:** the Entra registration and the cloud-platform egress (**PL7e**: the conductor's reading is that they are the cloud-platform shape's sign-in and belong there; the owner confirms or moves them); `kc_idp_hint` (say whether any ADR requires it; if one does, build it; if not, leave it); the sign-in page's GOV.UK assets row (PL7c's).
5. **Rule 13 and rule 4:** renewal and logout add no workspace action; every new route (the back-channel endpoint, the end-session redirect) has an access-control test (who may call it; what it answers to everyone else).
6. **Report:** the margin; the single-flight design; each provider refusal and what the person sees; the logout token's checks and the tests that plant each failing check; what the realm file now carries; what is left for PL7e.

## Round 2 (the conductor, 24 November 2026, 10:25 UTC): one fault and two gaps; sent back for fixing, never accepted narrower, and reported to the owner (every finding in this part is his)

1. **Fault: the live-update WebSocket proxy sends the Conduit the stored access token, not one from `accessTokenFor`, so renewal never applies to it** (`OspreyFlow_Core/apps/pages/server/stream.ts` about lines 164 to 170 and 189 to 190: `sessions.get` reads the record and the upstream is opened with `Authorization: Bearer ${record.accessToken}`; the renewal middleware is an Express `app.use(...)` at `app.ts` about line 309 and the upgrade is handled outside Express by `attachStreamProxy` in `start.ts` about line 138). **Once the access token's life ends (about five minutes), a reconnect of the delta stream with no page request before it sends the expired bearer; the Conduit refuses it and the browser gets 1008 "the Conduit refused the connection" until the person reloads a page.** The brief exists to end exactly this, and the new header of `accessToken.ts` ("the one place that says which token a session's calls carry, and every call site awaits it") is false for this call. **Do:** the upgrade path **awaits `accessTokenFor` for the session (single flight, the same renewal as every other call) before it opens the upstream; a refused renewal ends the session and closes the socket with the same plain words as a refused sign-in, never sending the old token**; correct the header if it then is true. **Red first: open a stream after the token's end: with a good provider it connects with the new token; with a refusing provider the socket closes and the upstream never sees the old bearer.** Say in your report **every other place that reads `accessToken` from a session without `accessTokenFor`** (grep) and fix each or say why not.
2. **Gap: `ValkeySessionStore` (the deployment's store, `start.ts` about line 103) has two new methods no test runs: `claim` (`SET … EX … NX`: the back-channel logout's replay refusal and "two at once, one wins") and `listKeys` (`SCAN MATCH`: how a logout finds the sessions to end).** The existing Valkey double (`test/server/store.test.ts`, `recordingClient`, about lines 112 to 146) ignores a fifth `NX` argument, returns "OK" whatever the key holds and has no `scan`: **it accepts what real Valkey refuses (rule 15).** **Do:** make the double model Valkey's refusals (`NX` on an existing key answers null; `EX` expires; `SCAN` with `MATCH` and a cursor), and **test both methods through `ValkeySessionStore` against it: a second `claim` of one key is refused, a claim after expiry is accepted, `listKeys` returns exactly the matching keys across cursors and nothing mangled; red first: a `claim` that drops `NX`, and a `listKeys` that returns nothing.** (A real-Valkey test is welcome from your own lease on stack a on this Mac if a live test file is already wired; **a new live test file cannot be wired by you: the lists are protected**; say in your report if you add none.)
3. **Gap: ADR-050 Amendment 4 names the invariant "an expired access token is renewed with no redirect in the middle of a form post" (`spec/06_DECISIONS.md` about lines 41347 and 41348), and no case drives a successful renewal of a token that has already ended, or a successful renewal on a POST.** Every successful-renewal case advances to `LIFE - MARGIN` (token still valid) and uses a GET; the only POSTs are the refusal table's form post (303 to sign-in) and sign-out. **Do:** add (a) a successful renewal after the token's end (`advance` past `LIFE`) on a GET, (b) the same on a POST of a form: **the POST goes through with the new token, no redirect to sign-in, the body not lost**; **red first with the verifier's mutation (`case "renewed"` returning `finish("unavailable")` when expired) and with the renewal skipped on POST.**
