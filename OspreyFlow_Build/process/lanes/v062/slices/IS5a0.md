## What (in this order; each with a test red first, and a planted fault at the shape the code really sees: rule 15)

1. **Static assets at `/assets/pages/*` (ADR-152 decision 7).** A static route serving only the built asset folder (`apps/pages/dist/assets`): content-hashed file names, `Cache-Control: public, max-age=31536000, immutable`, correct content types, no directory listing, no dotfiles, **a path outside the folder is refused (a planted `..%2f` and an encoded variant, red then green)**, HEAD allowed, other methods refused. Served without a session (a sign-in page needs its stylesheet) and the security headers at `app.ts` about line 89 stay (read them: a content policy that allows `'self'` styles and scripts and **no inline script or style**; if they do not already, say so and fix, with a test).
2. **The stylesheet.** The build produces one hashed stylesheet from `packages/design` (read how the workspace composes `tokens.css`, `primitives.css`, `scale.css`, `panelType.css` and the fonts list `packages/design/fonts.json`; **use the same files, copy none of their rules into the pages tree**). **Fonts:** serve exactly the fonts `fonts.json` names for the Default tree and no more; **GDS Transport is the GOV.UK tree's and has two conditions (ADR-152 Amendment 2): the Default tree never loads or serves it, with a test (planted: the face added to the Default build; red).** If `fonts.json` does not say which tree a face belongs to, say so and ask in your report (do not guess a licence).
3. **The Default tree's layout and route convention.** `apps/pages/tree-default/` holds the templates; `apps/pages/modules/` holds the page's client TypeScript (ADR-152 decision 6). **Move `layout.njk` to the convention and give it:** the stylesheet link, `<html lang="en-GB">`, a skip link to `<main id="main">`, a header with the product name and a sign-out form (POST, with the CSRF token), a `<main>` landmark, a `title` block, a `page-data` block, a footer-less body (nothing the specification does not name). **A route module convention:** a page is a module exporting `{ id, path, methods, handler }`, where `id` is its `FUNCTIONS.yaml` row; the server registers them through the existing `extraRoutes` hook behind the session check (an unsigned request is redirected to sign-in as the home page does today) and the CSRF check on every non-GET. Tests: an unsigned request to a registered page is sent to sign-in; a POST without the token is refused; two modules claiming one path, or one `id` not in `FUNCTIONS.yaml`, fail at start-up in words (planted both). **Ship one throw-away fixture page in the tests only** (not in the product tree) to prove the convention; the first real pages are IS5a and IS3.
4. **The client-script bundle.** Add esbuild to `apps/pages` (**a new dependency: its licence-register entry and `make licence-check` must pass; check the register's rules and do it as the register says; if esbuild is already in another workspace's lockfile, say so**). `scripts/build.mjs` bundles `modules/*.ts` entry files to hashed ES modules in `dist/assets`, **no React and no drawing library** (`no_react_check.mjs` stays green and gets a planted case for a module that imports React), **no inline script ever** (a test fails if any built template contains an inline `<script>` with code), and **every page must work with scripts off** (the convention's test renders the fixture page and asserts its core content is in the HTML). A module may import from `packages/glass-shared` (plain TypeScript); the bundle step must resolve the package's source: say how.
5. **The image.** `apps/pages/Dockerfile`: the COPY lines for the sources the bundle and the stylesheet need (`packages/design`, `packages/glass-shared/src`, `packages/schemas/generated` as the bundle imports them), nothing else; `tests/harness/test_dockerfiles_numeric_user.py`, `tests/glass_trees/test_pages_image_carries_no_react.py` and `test_harness_frontend_copies.py` stay green; the image's COPY lines are listed in your report. (Nothing builds the image in CI yet: the Dockerfile's own header says so; do not add a render of it to any deployment: that is PL7a2.)
