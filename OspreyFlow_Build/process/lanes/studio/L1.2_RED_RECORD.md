## Which Postgres the long Python run used

The second review's long run (1426 of 1427 passing) set `POSTGRES_PORT=55433` and took no lease. The
lease was held by the case lane, whose live suite was running on the machine at the same time. It
recorded `test_a_pipeline_recipe_runs_through_the_pipeline_runner` failing with `asyncpg … pool is
closed`; that test passes on its own. It reached a Postgres there: `test_route_rights.py`'s two live cases, which need one on 55433, passed in
the same session. This lane started none, so it was the throwaway Postgres the case lane had up for its
own live suite, used without the lease and since stopped (those two cases now fail to connect). That
failure is therefore not a measurement of this branch: the run used another lane's database, unleased,
while that lane's own live tests ran against it.
