## The planted changes

Each plant goes just after `_withdraw_dropped_rows` in `load_with_rules`, at the point the old code
withdrew, inside the load's transaction. It reads the dropped keys as the old planner did
(`sink.dropped_row_keys`), takes their recorded link ids, and withdraws them with
`graph.withdraw_elements([], links, load_id, tx)`. That is the call and argument shape the old
`_withdraw_dropped_rows` made, with `report.withdrawn_edge_ids` set as it set it.

- **a** — link withdrawal restored: every dropped row's links withdrawn.
- **b** — as a, less every link another kept row of any recipe or case records: the old
  `elements_kept_by_other_rows`, its SQL over `loaded_row_keys`.
- **c** — as a, less every link an unreverted load's record lists (`touched_edge_ids`), the dropped
  rows' loads and this load left out: the old `elements_in_other_records`, its SQL over
  `recipe_runs.load_records`.

b and c read the real store's pool (`sink._ledger._pool`), so they are meaningful against the real
ledger alone. Against the unit file's fake ledger they fail with `AttributeError`. That proves nothing
about the branch, so those rows are not counted (rule 15's second paragraph).
