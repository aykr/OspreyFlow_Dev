# studio-b · L1.9 part 1 plan (11 November 2026, on the test server)

Spec: ADR-148 decisions 4 and 7; ADR-142 Amendment 8 (decisions 2, 3, 7); ADR-140 Amendments 13 and 15 (the
connector pattern this extends); 09 §2 "Connections beyond files"; the build plan's row L1.9. Part 1 only:
no cloud-platform profile, no IAM role wiring, no egress render (part 2, after P7 merges).

**A. Schemas (own commit at the head).** `packages/schemas/sources.py`: connection kinds `s3` and `athena`.
`S3ConnectionSettings` (region, bucket, the prefix sources may read under) and `AthenaConnectionSettings`
(region, workgroup, catalog, the databases sources may read, an optional results location). **Neither has a
secret or a key field**: both sign in as the deployment's own cloud identity (part 2: the namespace's IAM
role). `S3Read` (a folder under the connection's prefix, CSV or Parquet) and `AthenaRead` (a table
`database.table` or a named query's id, one of the two). Names only, never an expression (rule 8).
Dependency: `botocore` (Apache-2.0; already in uv.lock at 1.43.114 through cloudpathlib's extra) for Athena.
S3 uses pyarrow's own S3 filesystem, as the media store does: no new dependency.

**B. Readers** (`services/ingest/connectors/s3_connector.py`, `athena_connector.py`), each landing as the
source's one CSV through the L1.6 path (`write_snapshot`), so the watch, the run, the confinement and the
rule gate are untouched. S3: objects listed and their sizes summed before any is opened (the byte cap,
refused whole with the typed words, rule 2), an object-count cap, Parquet's row count read from its footer
before its rows. Athena: a table read as `SELECT * FROM "db"."table"` built from checked names; a named
query only if it is in the connection's workgroup and database and is a SELECT or WITH; results paged
(1,000 a page) with the row, byte and page caps. `connector_reads.py`: dispatch, *Test connection*, the
host checked against the egress allow-list (`<bucket>.s3.<region>.amazonaws.com`,
`athena.<region>.amazonaws.com`), and `Readers` gaining an S3 filesystem and an Athena client factory a
test can stand a fixture in for.

**Tests first (each shown red):**
1. `tests/connectors/test_s3_connector.py` — golden files (CSV and Parquet under a prefix → the source's
   CSV), the byte cap, the object cap, the Parquet row cap read from the footer, an empty prefix refused,
   a key outside the prefix never read, hidden objects skipped.
2. `tests/connectors/test_athena_connector.py` against a **recorded fixture** behind the real botocore
   client (its own serialiser and error parser): golden file, paging, and the refusals Athena makes — a
   bad query, a missing table, an unauthorised principal, a named query in another workgroup, a page size
   over 1,000, a results location missing; plus our own: a non-SELECT named query, a database not named.
3. `tests/services/api/test_cloud_connector_access.py` — rules 3 and 4 on every read path: register,
   Refresh now, Test connection, the connection listing; another dataset's source refused.
4. `tests/connectors/test_s3_connector_live.py` — the same golden files and refusals against SeaweedFS
   (`studio-b-seaweedfs`, started and stopped by me), skipped unless its endpoint is given.
5. Schemas: no secret field on either kind; bad names refused.

**C. Glass.** Admin › Connections (`src/admin/sections/Connections.tsx`, L1.6's own file; not Admin › Models)
gains the two kinds, with no secret field and words saying so; the register wizard's read step gains the S3
folder and format, and Athena's table or named query. Keyboard cases in `admin.spec.ts` and
`sources-connectors.spec.ts`; registry ids, the harness states for axe in three themes and the CI
SeaweedFS service as diffs in this folder.

**D. Spec.** 09 §2 gains "S3 and Athena (L1.9 part 1)"; the ADR-140 amendment's text drafted here for the
number the orchestrator reserves.
